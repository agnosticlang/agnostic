## Скалярные типы

| Тип | Значение |
|---|---|
| `i64` | 64-битное знаковое целое |
| `i32` | 32-битное знаковое целое |
| `i8` | 8-битное знаковое целое |
| `u64` | 64-битное беззнаковое целое |
| `u32` | 32-битное беззнаковое целое |
| `u8` | 8-битное беззнаковое целое |
| `f64` | 64-битное число с плавающей точкой |
| `bool` | булев тип |
| `string` | строка |
| `int` | синоним `i64` |
| `float` | синоним `f64` |

Литерал с `.` (`3.14`) имеет тип `f64`, литерал без точки (`3`) имеет тип `i64`. Целочисленный литерал
также принимает тот тип, в котором используется, если значение в него помещается: `var b u8 = 200`
и `3.14 + 2` компилируются, `var b u8 = 256` нет. `%` и битовые/сдвиговые операторы не принимают операнды `f64`.

Нет и отдельного типа `char`: байт, полученный при индексации строки или через `stdio.ReadChar`, — это `int`.

## Вывод типов

`var x = expr` выводит тип `x` из `expr`. `var x int = expr` явно объявляет тип и проверяет `expr` на соответствие ему. Объявление без инициализатора (`var x int`) получает нулевое значение этого типа.

## Указатели

`&x` берёт адрес `x`. Тип указателя записывается как `*T`, а `*p` читает или записывает значение, на которое он указывает:

```agn
func set(p *int, v int) {
    *p = v
}

func main() {
    var x int = 5
    var p *int = &x
    *p = 99
    set(&x, 7)
}
```

`*[N]T` неявно приводится к `*T`, указателю на первый элемент. Так байтовый массив передаётся как буфер:

```agn
var buf [64]u8
var n Option<int> = os.ReadFd(fd, &buf, 64)
```

## Массивы

Фиксированного размера, размер и тип элемента указываются перед тем, как переменную можно использовать:

```agn
var arr [8]int
arr[0] = 5
var first int = arr[0]
```

Размер массива — целочисленный литерал времени компиляции. Литералов массивов нет, и срезов тоже нет: каждый элемент задаётся отдельно или в цикле.

## Типы функций

Записываются как `func(T1, T2) -> R`, либо `func() -> R` без параметров, либо `func(T1)` с выводимым `void`-возвратом. См. [Функции и замыкания](/ru/functions/).

## Приведение типов

`expr as T` явно преобразует значение:

```agn
var big int = 300
var low u8 = big as u8
var half = 7 as f64 / 2.0
var flag int = true as int
var addr u64 = &big as u64
```

| Из | В | Результат |
|---|---|---|
| целое | целое | усекается до ширины целевого типа или расширяется: знаково из знакового типа, нулями из беззнакового |
| целое | `f64` | ближайшее значение `f64` |
| `f64` | целое | усекается к нулю; значение должно помещаться в целевой тип |
| `bool` | целое | `0` или `1` |
| указатель или `string` | указатель или `string` | тот же адрес с новым типом |
| указатель | `i64` или `u64` | адрес |
| `i64` или `u64` | указатель | адрес |

Любое другое приведение является ошибкой компиляции. Приведения числа к `bool` нет; вместо него используйте сравнение (`x != 0`).

`as` связывает сильнее бинарных операторов и слабее унарных: `-x as u8` означает `(-x) as u8`, а `a + b as i64` означает `a + (b as i64)`.

## Правила проверки типов

Значение неявно преобразуется только в этих случаях:

- из числового типа в тип, который вмещает все его значения: `i8` в `i32` в `i64`, `u8` в `u32` в `u64`, беззнаковый тип в более широкий знаковый (`u8` в `i32`, `u32` в `i64`), а также `i8`, `i32`, `u8`, `u32` в `f64`;
- из целочисленного литерала, в том числе с минусом, в любой числовой тип, который вмещает его значение;
- из `*[N]T` в `*T`;
- из `*u8`, `*i8`, `*[N]u8` или `*[N]i8` в `string`.

Любое другое преобразование требует явного [приведения](#приведение-типов) или является ошибкой компиляции. Сужение (`i64` в `i8`), смена знаковости (`i32` в `u32`), `f64` в целое, а также `i64` или `u64` в `f64` теряют значения на части входных данных, поэтому записываются через `as`. `bool` и числа не преобразуются друг в друга, указатели не преобразуются в числа и обратно. Условия `if` и `for` и операнды `!`, `&&` и `||` должны иметь тип `bool`. `==` и `!=` требуют операндов совместимых типов, а `<`, `<=`, `>`, `>=` требуют числовых операндов.

Два операнда арифметического, битового оператора или сравнения сначала приводятся к одному типу. Целочисленный литерал принимает тип другого операнда (`x + 1` при `x i8` имеет тип `i8`); иначе операнд меньшего типа преобразуется в тип другого по правилам выше (`i8 + i64` имеет тип `i64`). Операнды, которые ни одно правило не приводит к общему типу, например `i32` и `u32` или `f64` и `i64`, дают ошибку компиляции. Правый операнд `<<` и `>>` задаёт величину сдвига и может быть любого целого типа.

Сообщение об ошибке подсказывает, какое приведение или сравнение написать:

```
error: type mismatch in variable 'n': declared as i64, initialized with bool (convert explicitly with 'as i64')
error: condition must be bool, got i64 (compare instead, e.g. 'x != 0')
error: type mismatch in variable 'b': declared as u8, initialized with i64 (constant 256 does not fit in u8)
error: mismatched operand types f64 and i64 (convert one side explicitly with 'as')
```

## Дженерики и сопоставление с образцом

Обобщённые *структуры*, разрешаемые на этапе компиляции монолиформизацией, существуют — см.
[Обобщённые структуры](/ru/structs/#обобщённые-структуры-дженерики). Обобщённые *функции* тоже есть, через
параметры `comptime` вместо синтаксиса `<...>` — см. [Обобщённые
функции](/ru/comptime/#обобщённые-функции). Выражения `match`/`switch` нет: ветвление — это только
`if`/`else` (см. [Управляющие конструкции](/ru/control-flow/)).
