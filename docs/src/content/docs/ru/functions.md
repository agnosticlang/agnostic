## Функции как значения

Литерал функции имеет тот же синтаксис параметров и возврата, что и именованная функция, только без имени:

```agn
var double func(i64) -> i64 = func(x i64) -> i64 {
    return x * 2
}
```

Именованную функцию верхнего уровня тоже можно использовать как значение — по имени, без скобок вызова:

```agn
func linuxWrite(fd i64, buf i64, len i64) i64 {
    return 1
}

var writer func(i64, i64, i64) -> i64 = linuxWrite
```

## Замыкания

Литерал функции захватывает переменные, на которые ссылается из окружающей области видимости, по ссылке:

```agn
func makeCounter() func() -> i64 {
    var count i64 = 0
    var next func() -> i64 = func() -> i64 {
        count = count + 1
        return count
    }
    return next
}

func main() {
    var counter func() -> i64 = makeCounter()
    stdio.Println(counter())   // 1
    stdio.Println(counter())   // 2
    stdio.Println(counter())   // 3
}
```

`count` живёт дольше собственного кадра вызова `makeCounter`, потому что «убегает» в возвращаемое замыкание; компилятор это обнаруживает и размещает в куче любую локальную переменную, захваченную «убегающим» литералом функции, вместо того чтобы класть её на стек.

## Вызов значения-функции

```agn
func apply(f func(i64) -> i64, x i64) i64 {
    return f(x)
}

apply(double, 21)
```

## Поддержка по бэкендам

Функции как значения и замыкания работают только под `--backend=llvm`. `--backend=nvm` отклоняет любой литерал функции или использование имени функции как значения на этапе компиляции: инструкция `CALL` в Novaria Virtual Machine принимает только адрес байткода, известный на этапе компиляции, косвенного вызова через указатель на функцию времени выполнения не существует.
