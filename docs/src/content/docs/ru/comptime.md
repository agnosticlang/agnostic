Блок `comptime` интерпретируется на этапе компиляции обходчиком дерева ещё до того, как запустится
кодогенерация. Он умеет вычислять произвольные значения — арифметику, циклы, вызовы других функций
верхнего уровня, — и результат подставляется в программу как литерал. Всё, что блок `comptime` не может
вычислить (кроме условия `if`), просто остаётся обычным кодом времени выполнения, поэтому уже написанный
код условной компиляции продолжает работать без изменений.

## Вычисление на этапе компиляции

```agn
func fib(n int) int {
    if n < 2 {
        return n
    }
    return fib(n - 1) + fib(n - 2)
}

func main() {
    comptime {
        var fibResult int = fib(10)
    }
    stdio.Println(fibResult)   // 55, вычислено на этапе компиляции

    comptime {
        var sum int = 0
        var i int = 0
        for i < 5 {
            sum = sum + i
            i = i + 1
        }
        var total int = sum
    }
    stdio.Println(total)   // 10
}
```

`var`, присваивание, `for`, обычные выражения-операторы и вложенные блоки `comptime` интерпретируются.
Значение, вычисленное так (`fibResult`, `total`), привязывается на всю оставшуюся часть окружающей
функции — как и любая другая переменная в Agnostic, привязки `comptime` относятся к области видимости
функции, а не блока, — и каждое дальнейшее упоминание этого имени заменяется на литерал ещё до того, как
его увидит кодогенерация. Ни одному бэкенду не нужно знать, что значение когда-то было вычислено в
comptime — он всегда видит только обычный литерал.

Оператор, который вычислитель не может обработать (вызов метода с receiver'ом, литерал структуры,
всё, что ссылается на состояние, доступное только во время выполнения), оставляется как есть
и проверяется типами как обычный код времени выполнения — это не ошибка, а предусмотренный откат,
благодаря которому продолжает работать паттерн выбора платформы ниже.

Фиксированный бюджет в 10 000 000 выполненных операторов защищает от бесконечного цикла `comptime`;
превышение — ошибка компиляции.

## Условная компиляция

`comptime if` работает так же, как и раньше: условие вычисляется на этапе компиляции, и в скомпилированную
программу попадает только выбранная ветка — другая удаляется ещё до кодогенерации. В отличие от обычного
оператора `comptime`, условие, которое не удаётся вычислить на этапе компиляции, — это ошибка компиляции.

```agn
struct Platform {
    write func(i64, i64, i64) -> i64
}

func linuxWrite(fd i64, buf i64, len i64) i64 {
    return 1
}

func stubWrite(fd i64, buf i64, len i64) i64 {
    return 0
}

func main() {
    var platform Platform
    comptime {
        if TARGET_OS == "linux" {
            platform.write = linuxWrite
        } else {
            platform.write = stubWrite
        }
    }
    stdio.Println(platform.write(1, 0, 4))
}
```

Условием может быть любое вычислимое на этапе компиляции выражение, а не только сравнение со встроенными
константами — работают арифметика, вызовы функций и сочетания через `&&`/`||`/`!`.

### Доступные константы

- `TARGET_OS`: значение `--target-os=` (`linux`, `freebsd`, `windows` или `hurd`).
- `TARGET_ARCH`: целевая архитектура (`x86_64`).
- `MEM_MODE`: значение `--mem=` (`arc`, `manual` или `orc`).

## Обобщённые функции

Параметр функции, помеченный `comptime`, полностью разрешается на этапе компиляции и не попадает в
рантайм-сигнатуру функции. Если объявить его как `type`, это параметр-тип; если объявить как любой другой
тип (`int`, `bool`, `string`, `f64`) — это параметр-значение времени компиляции:

```agn
func max(comptime T type, a T, b T) T {
    if a > b {
        return a
    }
    return b
}

func addN(comptime n int, x int) int {
    return x + n
}

func main() {
    stdio.Println(max(int, 3, 7))     // 7 — T = int
    stdio.Println(addN(5, 10))        // 15 — n = 5
}
```

Тип или значение передаётся как обычный позиционный аргумент — `max(int, 3, 7)`, а не `max<int>(3, 7)` —
и для параметра-значения может быть любым вычислимым на этапе компиляции выражением (`addN(2 + 3, x)`
работает так же, как `addN(5, x)`). Каждая отдельная комбинация comptime-аргументов, реально встреченная
в программе, компилируется в свою конкретную функцию (монолиформизация) — точно так же, как работают
[обобщённые структуры](/ru/structs/#обобщённые-структуры-дженерики). Обобщённая функция может вызывать
другую обобщённую функцию, используя собственные comptime-параметры, и внешние значения корректно
прокидываются дальше:

```agn
func identity(comptime T type, x T) T {
    return x
}

func scaleAndAdd(comptime T type, comptime factor int, x T) T {
    return identity(T, x) * factor
}
```

Пока не поддерживается: comptime-параметры у методов (функций с receiver'ом), использование
comptime-значения в позиции типа (размер массива, известный на этапе компиляции), и вывод типа-аргумента
из обычного аргумента вместо явной передачи.
