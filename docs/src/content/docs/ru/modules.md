## Импорт

```agn
import "stdio"
import "math"
```

`import "name"` ищет файл `name.agn` в таком порядке: рядом с файлом, который выполняет импорт, затем в `stdlib/` относительно текущей рабочей директории, затем в `stdlib/` рядом с бинарником компилятора, затем в `../share/agnostic/stdlib/` относительно бинарника компилятора (раскладка, используемая установленными пакетами). Побеждает первое совпадение.

## Вызов функции из модуля

Любая функция, вызываемая извне своего файла, должна иметь модификатор `pub` (см. [Синтаксис](/ru/syntax/)); функция без него невидима для импортирующих файлов и даже не проверяется типами при загрузке этого файла как модуля. Вызов импортированной функции: `модуль.ИмяФункции(...)`:

```agn
package main

import "math"
import "stdio"

func main() {
    stdio.Println(math.Max(3, 7))
}
```

## Вызов внутри одного модуля

Функция, объявленная в файле модуля, может вызывать соседнюю функцию из того же файла по её простому имени, без префикса модуля:

```agn
// внутри string.agn
pub fn is_empty(s string) int {
    if len(s) == 0 {
        return 1
    }
    return 0
}
```

Здесь `len` разрешается в `string.len`, потому что обе функции объявлены в одном файле. Это разрешение зависит от того, в каком файле написан вызов, а не от `pub`: неэкспортированный вспомогательный код тоже нельзя вызвать таким способом, потому что он вообще не был скомпилирован.

## Отсутствие защиты от циклов

Обнаружения циклов импорта, кроме как отказа повторно разбирать уже загруженный в текущей компиляции путь, нет; на практике граф модулей стоит держать ациклическим.

## package main

`package main` — это не модуль, который импортируют извне; это точка входа, компилируемая напрямую, и `pub` на её функциях не нужен.
